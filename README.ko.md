# agent-scaleout (한국어)

**집이나 사무실에 놀고 있는 컴퓨터들을 코딩 에이전트용 작업 풀로 묶어요.**
한 대(**오케스트레이터**)가 Claude Code · Codex · Gemini CLI(또는 아무 명령) 일을 대기열로 모아 두고 이렇게 해요.
- 각 **노드**의 메모리 · 디스크 · 부하를 보고, 가장 한가한 노드에 일을 나눠 줘요.
- 결과를 받아 오고, 멈춘 일은 다른 노드에서 다시 돌려요.
- 노드 디스크가 차기 전에 정리해요.

- **서버 · 클라우드 필요 없음.** SSH만 써요. 오케스트레이터는 Python 3.9+ 파일 하나(기본 라이브러리만)이고, 노드는 작은 셸 · PowerShell 스크립트예요.
- **에이전트 · 계정은 노드마다 달라도 돼요.** 각 노드에 설치 · 로그인된 에이전트를 그대로 써요. 서로 다른 Claude 계정, Codex, Gemini, 직접 만든 명령 다 돼요.
- **저사양 PC를 막 이어 붙여도 돼요.** 디스크 · 메모리가 기준보다 적은 노드에는 일을 안 보내고 자동으로 정리해요.
- **한 번 붙이면 끝.** 노드 붙이기는 오케스트레이터에서 명령 하나, 또는 노드에 한 줄 붙여넣기예요. 그 뒤로는 오케스트레이터가 관리자처럼 다 해요(업데이트 · 정리 · 스킬 · 러너 · 명령).

> 상태: **v0.2 초기 버전.** macOS 오케스트레이터 + macOS 노드는 매일 쓰고 있어요. **Linux · Windows 노드는 코드만 있고 실제 기기에서 시험하지 못했어요.**

## 설치 (오케스트레이터에서 한 번)
```bash
curl -fsSL https://raw.githubusercontent.com/yuna-studio/agent-scaleout/main/install.sh | sh
scaleout install-daemon   # 권장: 배정 · 회수 · 복구를 뒤에서 계속
```
오케스트레이터의 SSH 서버가 켜져 있어야 초대가 돼요. macOS는 시스템 설정 → 일반 → 공유 → 원격 로그인이에요.

## 노드 붙이기
노드에 필요한 건 세 가지예요. SSH 서버(초대가 켜 줘요), 로그인된 코딩 에이전트, 잠들지 않게 하는 전원 설정.

- **A. 오케스트레이터에서만:** `scaleout add build-01 kong@192.168.0.10`
  - 노드 비밀번호를 한 번만 물어요.
  - 패키지 설치, 실행기 등록, 호스트 키 고정(yes/no 질문 없음), 시험 일까지 알아서 해요.
- **B. 노드에 한 줄:** `scaleout invite build-02` (Windows는 `--os windows`)
  - 나온 한 줄을 노드 터미널(Windows는 관리자 PowerShell)에 붙여요. 원격 데스크톱으로 넣어도 돼요.
  - SSH 서버를 켜고, 오케스트레이터에서 패키지를 받아 설치하고, 등록과 키 교환까지 해요.
  - 초대 키는 24시간 · 1회용이고, 등록 말고는 아무것도 못 해요.
- **다른 망의 노드:** 오케스트레이터에 공개 SSH 주소가 있으면 `scaleout init --tunnel-host 주소 [--tunnel-proxy "cloudflared access ssh --hostname %h"]`로 켜요. 그러면 노드가 역방향 터널로 붙어요. 같은 망이면 필요 없어요.

## 일 맡기기
```bash
scaleout status                                    # 노드별 상태 · 남은 메모리 · 디스크 · 부하 · 일 · 에이전트
echo "api 테스트 돌리고 실패만 요약해" | scaleout run -d ~/src/app
id=$(scaleout submit -f task.md --tags xcode); scaleout wait "$id"
scaleout run --sync ~/work/proj -f task.md        # 오케스트레이터 폴더를 노드로 보내 작업 → 다시 받아 옴
scaleout exec build-01 -- df -h                    # 노드에서 아무 명령
```
- Claude Code 안에서는 「scaleout 서브에이전트로 …를 남는 기기에서 돌려 줘」라고 하면 돼요.
- 노드 에이전트는 지금 대화를 모르니, 지시만 보고도 일할 수 있게 써 주세요.

## 자원 지킴 · 자동 복구
- **기준 아래면 일을 안 보내요:** 디스크 5GB 미만, 메모리 15% 미만인 노드요.
- **메모리를 보고 몇 개까지 돌릴지 정해요:** 일마다 필요한 메모리(`--mem`, 아니면 같은 종류 일이 실제로 쓴 양, 아니면 에뮬레이터 7.5GB · 시뮬레이터 4.5GB · 폰 3.5GB · 그 밖 3GB)가 노드의 남은 메모리에 들어갈 때만 더 보내요. 시뮬레이터 · 에뮬레이터 개수 고정 제한은 없어요. 폰은 한 대에 한 일씩이에요.
- **디스크 정리:** 8GB 미만이면 오래된 작업 · 패키지 캐시를 지우고, 쉬는 레포 작업 폴더(다음 빌드용 캐시가 든 사본)를 오래 안 쓴 것부터 20GB가 빌 때까지 지워요(`cleanup_target_disk_gb`). 한 시간에 한 번, 디스크가 꽉 차 일이 멈췄으면 10분에 한 번이에요. 5GB 미만인데 그래도 모자라면 홈 안 캐시까지 지워요. 3일 넘게 안 쓴 작업 폴더는 그냥 지우고, 일하는 중인 폴더는 건드리지 않아요. 오케스트레이터 머신도 같은 정리를 받아요.
- **Xcode 빌드 캐시:** Xcode 는 폴더 경로마다 빌드 캐시(DerivedData, Flutter 앱 하나에 4~8GB)를 만들고 지우지 않아요. 작업 폴더를 지울 때 그 폴더 캐시도 같이 지우고, 원래 폴더가 없어진 캐시도 정리 때 지워요(빠진 외장 디스크 것은 남겨요).
- **멈춘 채 남은 작업 폴더:** 끝 표시가 없는데 프로세스도 없고 하루 동안 아무것도 안 쓴 작업은 지워요. 작업 칸 하나를 계속 차지하지 않게요. `bench --load` 가짜 일이 죽으면 그 메모리도 같이 풀려요.
- **배정:** 넣을 자리(작업 수 · 메모리 · 부하 · CPU 칸 · 디스크)가 있는 노드 중, 이 일을 받은 뒤 가장 덜 차는 곳으로 보내요(작업 수 ÷ 몫, 부하 ÷ 코어×2, 메모리, 이 일이 남은 디스크에서 차지할 몫). 비슷하면 빠른 머신(`scaleout bench` 전체 코어 속도)이 받고, 맥은 맥만 되는 일에 남겨 둬요. Android 일은 맥 아닌 머신부터, 아무 데나 되는 일도 맥을 덜 쓰고, 태그 없이 iOS 같아 보이는 일은 맥으로 가요.
- **멈춘 일 · 사라진 노드:** 하트비트가 5분 끊기거나 노드가 10분 안 보이면 다른 노드로 다시 맡겨요(기본 2번, 15분 동안은 그 노드를 피해요). 실행기가 빠져 있거나 systemd 가 멈춰 세웠으면(failed) 다시 등록해요.
- **노드 메모리 지킴:** 노드 남은 메모리가 12% 아래면 노드가 일을 시작하지 않고 쥐고 있어요. 10분 넘게 못 시작하면 오케스트레이터가 다른 노드로 옮겨요. 한 대에 에이전트가 몰려 스왑으로 멈추는 걸 막아요.
- **실기기:** 노드에 꽂힌 안드로이드 · 아이폰 수를 세요(`scaleout status`의 `A1 I1`). `--tags android-device`나 `ios-device`를 붙인 일은 빈 폰이 있는 노드에만, 폰 하나에 한 일씩 가요. 에뮬레이터 하나가 메모리 약 4.5GB를 쓰니, 8GB 노드는 실기기를 꽂아 쓰면 좋아요.
- **CPU도 봐요:** 1분 부하(load)가 코어 수의 2배(`max_load_per_cpu`)를 넘는 기기에는 새 일을 안 줘요. 일이 없어도 마찬가지예요(CI 같은 다른 일일 수 있어서요). 노드 실행기도 시작 직전에 같은 기준을 봐요.
- **CPU 칸:** 기기마다 벤치로 잰 칸 수(M1 2 · M4 3 · M4 Pro 5)가 있고, 빌드 · 전체 테스트 · 시뮬레이터 · 에뮬레이터 일은 2칸, 나머지는 1칸이에요(태그와 지시문 낱말로 알아보고, `--cpu N`으로 정할 수도 있어요). 칸이 차면 더 안 주지만, 부하가 코어 수보다 낮으면 한 개 더 줘요.
- **기기 전체 정리:** Docker prune, 시뮬레이터 정리는 사람이 `scaleout cleanup 노드 --deep`으로 부를 때만 해요.

## 오케스트레이터도 일해요
- **`scaleout local on [--max-jobs N]`:** 오케스트레이터에 여유가 있으면 먼저 직접 일하고, 바쁘면 노드로, 아무도 여유가 없으면 대기열에서 기다려요. 노드 설치 · SSH가 필요 없어요. `scaleout top`에는 `orchestrator` 한 줄로 보여요. `scaleout local off`로 꺼요(도는 일은 끝까지 해요).
- **레포 일:** 내장 디스크(`~/.local/state/scaleout/local`)의 사본에서 해요. 처음 한 번만 복사하고 다음부터는 바뀐 부분만 보내요.
- **macOS 주의:** launchd로 도는 Apple 것이 아닌 프로그램(Claude Code · Homebrew/uv 파이썬 · node)은 외장 디스크를 건드리면 권한 창을 기다리며 멈춰요. worktree의 `.git`이 외장 디스크를 가리켜도 같아요. 그래서 데몬은 `/usr/bin/python3`로 돌고, 오케스트레이터의 일은 내장 디스크에서 해요. 다른 launchd 서비스의 작업 폴더도 내장에 두세요.

## 대시보드 · Claude 사용량
- **`scaleout top`:** 미니와 노드들의 메모리 · 스왑 · 디스크 · 부하 · 일 · 꽂힌 폰, 대기열, 최근 일, 지금 일하는 Claude 세션과 그 세션이 띄운 서브에이전트, 토큰(서브에이전트 포함)을 한 화면에 보여 줘요. 서브에이전트는 세션 프로세스 안에서 돌고 계산은 Anthropic 서버에서 해서 대기열에 세지 않아요. 데몬이 모아 둔 것만 읽고 새로 고침 사이에는 잠들어서 CPU를 거의 안 써요.
- **`scaleout usage`:** 이 기기의 모든 Claude 세션 토큰(5시간 · 오늘 · 7일)과 노드별로 한 일(토큰 · 비용 · 일 수 · 바빴던 시간)을 보여 줘요.
- **초대 한 줄:** 맥이면 Homebrew와 Claude Code가 없을 때 같이 깔아요(`--no-brew` · `--no-claude`로 빼기). 그 뒤 그 맥에서 `claude`를 한 번 실행해 로그인만 하면 돼요.

## 레포 작업 · 세션 공통 규칙 · 도구 맞추기
- **`--repo 폴더`:** 미니 git 레포의 지금 작업 트리(안 커밋한 변경 포함)를 노드로 보내 작업해요. git이라 바뀐 부분만 가요. 결과는 `scaleout/작업번호` 브랜치로 돌아오고, `--apply`를 붙이면 작업 트리에도 덮어쓰지 않게 반영해요(충돌은 알려 줌).
- **`scaleout claude-setup`:** 이 기기의 모든 Claude 세션에 적용돼요.
  - 전역 CLAUDE.md에 규칙 파일 가져오기 한 줄을 넣어요. 규칙 본문은 오픈소스에 있어서 업데이트를 따라가요.
  - 메모리 여유가 25% 아래이거나 부하(1분 load)가 코어 수의 3배를 넘고 건강한 노드가 있으면, 무거운 빌드 · 테스트 명령을 막고 노드로 보내라고 알려 주는 훅을 달아요(`SCALEOUT_LOCAL=1`로 우회).
- **`scaleout provision 노드`:** 이 기기와 같은 버전으로 노드에 설치해요(fvm · Flutter 버전들 · CocoaPods · Node · Firebase CLI · Android 플랫폼 · Java). Homebrew 설치 · Xcode(Apple ID) · Android 라이선스 동의처럼 사람이 할 일은 알려만 줘요.

## 벤치마크 · 부하 시험 · 메모리 튜닝
- **점수:** 100점 = M1 8GB 맥미니 한 대가 모바일 일(에이전트 + 빌드 + 테스트)을 하나씩 할 때. `scaleout add 이름 주소 --price 200000`으로 붙이면 알아서 재고 「100점 더함 · 만원당 5점 · 풀 200 → 300(1.5배)」처럼 보여 줘요.
- **명령:** `scaleout bench`(다시 재기) · `bench --load`(가짜 빌드 일로 실제 배정 경로 부하 시험) · `bench --history`(풀이 얼마나 커졌나) · `stats`(실제 일 · 실패 · 걸린 시간 · 일당 메모리) · `tune --apply`(잰 CPU 자리 수로 동시 일 수 맞추기, 데몬이 하루 한 번 자동. 메모리는 일을 나눠 줄 때마다 따로 봐요).
- **주의:** 같은 와이파이인데 서로 핑이 안 되면 공유기의 무선 격리(AP isolation) 때문이에요. 끄거나, 랜선으로 꽂거나, 터널 · Tailscale을 쓰세요.
- **macOS 외장 디스크:** 백그라운드 서비스(launchd)는 외장 USB 디스크를 못 읽어요. 작업 폴더 · 툴체인 · 캐시는 내장에 두세요(`relocate.sh`가 막아 줘요).

## 그 밖
- **스킬 동기화:** 오케스트레이터의 `~/.claude/skills · agents · commands`가 바뀌면 일 보내기 전에 노드로 자동 복사돼요(`scaleout sync-skills`로 직접도 가능).
- **GitHub 러너:** `scaleout runner add 노드 --org 조직`으로 노드에 자체 호스팅 러너를 깔아요.
- **보안:** 노드 키는 오케스트레이터에 「터널만 열 수 있게」 묶여 있어요. 노드 Claude는 강제 푸시, main · dev · release 푸시, 머지, 배포, `rm -rf`, `sudo`가 막혀 있어요(`~/.scaleout/settings/claude.json`).
- **무거운 폴더 옮기기:** `tools/relocate.sh`로 작업 폴더 · 캐시를 외장 SSD로 옮기고 링크를 남겨요. 경로는 그대로예요.
